Simple setup — Athena in claude.ai/code

The simplest way in: claude.ai/code connected to the team repo. Nothing to install, and it both reads the live repo and writes to it, so you can brainstorm, ask, and capture in one place. This is a recommendation, not a requirement; every tool in this guide reaches the same repo.

Your first session (five minutes):
  1. Open claude.ai/code, choose the cti-chief-of-staff repo, and say hello. You're talking with Athena, grounded in the team's shared memory.
  2. Use it for the base loop: think out loud, shape an idea, ask "what's the state of X" or "what's the latest on my experiment."
  3. When something is worth keeping, say: "Capture this in the right place, open the PR, merge it, delete the branch, and show me the file on main." That one sentence publishes it. The Update-the-repos section explains each part.

Companion: claude.ai chat + the Athena project

Good for reading and thinking on the go, including your phone. It knows the team context but cannot write to the repo. Hand anything worth keeping to claude.ai/code (see Update the repos).

Update the repos — the everyday workflow

The one part we all do the same way, and the section you will come back to. The six cards below are entry points, not steps in a sequence — pick the one that matches today's task.

The one rule: your update is real only when it shows on main, the official copy everyone sees on GitHub. Every path below ends with the same check: open the file on GitHub and see your words. If they are not there, your work is parked where nobody can see it.

Step 2 — which tool are you in?

From claude.ai chat — chat can read everything but cannot edit the repo. Many updates have been lost to this misunderstanding. Two ways to make it real:
  1. Work the update through with Athena until it says what you want.
  2. Say: "Give me a hand-off prompt for Claude Code." You get one message containing the text, the file, and the merge instructions.
  3. Open claude.ai/code, pick the repo, paste the prompt.
  4. Before closing, say: "Open the PR, merge it, delete the branch, and show me the file on main."
✅ Finish line: open the repo on github.com, find your file, see your words on main. (For a short edit, skipping Claude entirely and using the github.com path is also fine.)
From claude.ai/code — the main path for team updates.
  1. Pick the repo, then say what you want in your own words. Plain English is enough.
  2. Read what Claude wrote. Check names, dates, and anything attributed to you or a teammate. You own what lands in team memory.
  3. Say the whole ceremony in one sentence: "Open the PR, merge it, delete the branch, and show me the file on main."
  4. Click the link Claude gives you and confirm your words are there.
⚠️ The trap: every session works on a new branch. If the session ends before the PR merges, your work looks done in chat but is invisible in the repo. If it happens: new session, say "find my branch from earlier today, open the PR, and merge it."
✅ Finish line: your words visible on main, on github.com.
From Claude Cowork — good for longer working sessions (setup for the repos comes from Sathya).
  1. Start with: "Pull the latest before we work." Stale copies create conflicts.
  2. Work and review as usual — names, dates, claims.
  3. Getting it to GitHub has a quirk: git inside Cowork can jam the repo. So say: "Give me the Terminal commands to commit this on a branch, push it, and open the PR." Paste them into Terminal (Mac: Applications → Utilities → Terminal).
  4. Open the PR link GitHub prints, merge it, delete the branch.
  5. If you must stop midway: post in Slack which file you touched and on which machine — unsaved local edits are invisible to everyone, including the weekly report.
✅ Finish line: your words visible on main, on github.com.
Cowork + the Claude in Chrome extension — Cowork, with Claude doing the GitHub clicks in your browser. One-time setup: install Claude in Chrome, sign in, keep Chrome open (ask Sathya if the browser tools don't appear).
  1. Start with: "Pull the latest before we work."
  2. Work and review as usual — names, dates, claims. You own the result.
  3. Say: "Give me the Terminal commands to commit this on a branch and push it." Paste them into Terminal — git still happens there.
  4. Then: "Using Chrome, open the PR on GitHub, merge it, delete the branch, and show me the file on main." Claude drives github.com in your browser while you watch; it asks before anything irreversible.
  5. Beyond repo updates, the same idea works anywhere in the browser: "open the Week 3 Canvas page and check the learning goal," "read the backward-plan Doc and summarize what changed."
⚠️ Ground rules: watch it work — it uses your logins. Never passwords or payments (do those yourself). And keep it away from gradebooks or student submissions unless the task truly needs them.
✅ Finish line: Claude opens the file on main; you confirm your words are there.
Directly on github.com — best for small changes.
  1. Open the repo, click into the file, click the pencil icon. (New file: open the folder → Add file → Create new file.)
  2. Make the edit, click Commit changes…, write one plain sentence about what changed.
  3. Choose "Create a new branch and start a pull request" → Propose changes → Create pull request.
  4. Then all three, every time: Merge pull request → Confirm merge → Delete branch.
⚠️ The trap: people stop after "Create pull request." That is not the end — until you click Merge, the change is parked and invisible. If an edit of yours ever vanished, this is why.
✅ Finish line: back on the file with the branch picker showing main — your change is there.

Push how you work

Your workflow past the shared floor is yours to design. These are principles, the same ones we ask of students, so the team practices them too.

Tinker on real work

Pick something you actually do every week, not a demo. The test is whether next Tuesday is easier.

Start where it hurts

The task you dread, repeat, or postpone is the best first candidate.

Small loops

Change one thing, run it a week, keep or drop. A clean failure teaches more than a setup you never revisit.

One recommendation this week:
  • Let Claude in Chrome do one browser chore while you watch.

Then say what you tried in your stand-up: "one thing I tried with AI this week."
